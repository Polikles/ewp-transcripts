GUI workflow

Return to EWP Transcriber

Inspect and dry-run

Enter a server-side user-space path, or use Choose audio file. The native picker makes one session-only local copy so the browser does not need to disclose its hidden absolute path; that copy is deleted when the GUI stops. Symlinks and operating-system directories are blocked. Inspect reads media identity, streams, channels, duration, and warnings. Dry-run performs that inspection internally and additionally plans immutable outputs without writing anything, so clicking Inspect first is optional.

Choose paths

Direct entry accepts ordinary server-visible user-space paths, including new output directories. Browse output folder is a browser button, but the dialog belongs to the deployment operating system because the transcription server needs an actual filesystem path: Windows supplies it for WSL, while Zenity, KDialog, or Yad can supply it on desktop Linux. Headless and Docker deployments use direct paths inside explicitly mounted volumes. A browser upload-style directory picker is not used because it shares every file in the directory and does not expose a server path. Select a durable shared output root before Add saved results: the validated JSON is preserved in a hidden, content-addressed folder under that root, so saved queue work survives a GUI restart. Browser-picked audio is preserved there when staged. Reviews, revisions, and exports are also written under the chosen root. Selected files never go to a network service unless a separately confirmed provider operation sends transcript text.

Build and start a queue

Review dry-run, confirm it, and add the file to the staged table. Repeat for other accessible user-space files while keeping one shared output directory. Remove mistakes before selecting Start queue. Jobs then run one at a time.

LLM-assisted correction

Select the canonical result and a correction output root. Defaults for provider, model, and endpoint live under Provider settings. OpenRouter can read its key from the server environment or accept it for the active GUI server process. All browsers connected to that running process can use the key; it is never saved in the project, workspace, or browser and disappears when the GUI stops. This process-wide behavior is intentional for the supported single-user or single-organization pipeline; multi-user credential isolation is not currently planned. Treat keys as secrets and use a low provider spending limit. Confirm disclosure before generation. The backend and exact model are checked first. Every result is a non-final candidate; use Open candidate in manual review and verify it before applying.

Save and resume work

Named workspaces retain allowlisted non-secret fields, the active workflow step, staged transcription jobs, and completed or failed queue history across browsers and GUI restarts. The shared output directory supplies the default correction, review, translation, and dictionary roots. Set an optional Workspace storage directory to place workspace JSON files beside your normal backups, or leave it empty for the private application-state catalog. Remove selected work state deletes only that workspace JSON, never transcripts, reviews, exports, or durable selected-source copies. Clear current work state forgets the inactive queue and unsaved browser work after a warning; it never deletes saved workspaces or publication files and refuses while transcription is active. Explicit Save current work state first saves dirty transcript and translation review drafts. Unavailable dormant file fields and inactive queue items are omitted with visible counts instead of blocking recoverable state; malformed, changed, and prohibited paths still fail closed. Restoring a staged job re-hashes its durable source and re-plans its exact output. Interrupted GPU work is never revived. Optional auto-save checks every 60 seconds and writes only changed non-secret fields; it does not save unsaved editor text. API keys and confirmations are excluded.

Back up and remove saved work

A workspace JSON is an index, not a complete backup. Back up the entire chosen output directory, including its hidden .ewp-gui-sources directory, reviews, revisions, candidates, dictionaries, and exports. If Workspace storage directory points somewhere else, back up that directory too; with the default setting, include ~/.local/state/ewp-transcripts/gui-workspaces. Use a backup tool configured to include dotfiles and verify that the backup can be read before removing originals. Session upload copies under /tmp/ewp-transcripts-gui-selections are removed when the GUI server stops. Atomic .json.tmp/.media.tmp files under the output root are removed immediately after their copy attempt succeeds or fails. Hash-named files under .ewp-gui-sources are durable source records. Use Managed source copies under Saved work state to inventory them. Copies referenced by the current queue, the default or selected custom workspace catalog, or workflow lineage are protected and cannot be selected. Cleanup permanently deletes only explicitly selected copies that remain unreferenced after a fresh audit; publication artifacts are untouched. Custom workspace catalogs stored elsewhere are unknown, so audit them separately before cleanup.

LLM-assisted translation

Select the canonical result and, preferably, its manually verified source revision. Translation from raw ASR or an automated correction candidate remains possible, but the resulting artifact and summary identify that weaker source. Choose the exact LM Studio endpoint/model, target language, compatibility mode, and optional project dictionary. Confirm disclosure before generation. Every generated translation is non-final and requires manual review of meaning, omissions, additions, names, conventions, and style.

Semantic translation review

Open a generated candidate or skipped-assistance item in semantic review. The source is immutable; edit each target unit, then click Preview translation to save and validate the draft. Save translation draft remains available as an earlier checkpoint. Switching queue items saves dirty edits before opening each item's own draft. Empty targets fail by default. If an omission is intentional, enable Allow empty translation units before Preview; Apply requires the same setting. The final artifact and audit record each intentional omission, while TXT, HTML, SRT, and VTT leave it out without a blank placeholder. This confirmation is reset when a review is opened. Apply only after manually checking meaning, omissions, additions, uncertainty, names, conventions, register, and style.

Project correction dictionaries

Select directories containing exact canonical results and their latest compatible manual revisions. Generate a contextual proposal, inspect examples, and mark every mapping approved or rejected. A previous project dictionary carries both kinds of decisions forward. Save decisions before publishing one immutable dictionary with a deliberate project/version ID. Rejected mappings remain recorded and are never sent to correction providers.

Selecting dictionaries

Correction and translation forms can scan one explicit user-space catalog directory and list valid project dictionaries by project, edition-bearing ID, language or direction, and recorded hash. The separate JSON format version is not an edition number. Select one to fill its exact path, choose none, or retain direct-path entry for a custom location. Invalid JSON files are ignored; broad catalogs over 1,000 JSON files are rejected.

Safety and recovery

Refreshing or closing the browser does not stop a job. The server retains current queue state in memory and the application retains atomic filesystem job state. Until cancellation is implemented, stopping the server waits for the active transcription to finish.

Review and verified export

Select a canonical result JSON and one review output root. The GUI creates structured reviews, revisions, and exports paths below it unless manual paths are enabled. Prepare an editable draft, correct text and speaker attribution, and, when useful, expand Speaker names for this revision to rename anonymous speakers or add a revision-only speaker after isolating the relevant text. An unused revision-only speaker can be removed; a speaker assigned to text must first be reassigned or merged. Those labels and revision-only IDs are stored only in the review and accepted immutable revision; the canonical ASR result stays unchanged. Before a split, merge, or revision-only speaker addition, any dirty draft is saved as a checkpoint. Undo and Redo affect only the current browser draft; save and preview again before applying. Applying requires explicit confirmation that wording, speakers, punctuation, quotations, and sentence boundaries were manually checked. Only the resulting immutable revision is offered to the verified export action. The current saved review is restored after refresh; Clear requires confirmation and does not delete files. In another browser or later GUI run, enter the same persistent output root and select Restore saved review.

What comes next

Translation review, dictionary proposal management, richer recovery/navigation, and remaining operator conveniences will be added in later GUI slices; use the CLI runbook for production workflows not yet exposed here.
