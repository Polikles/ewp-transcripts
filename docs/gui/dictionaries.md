# Dictionaries

Use this guide with the matching stage in EwP Transcripts. Interface language does not change recording or translation language.

1. Choose dictionary library: Refresh a catalog, add a dictionary file, create a blank dictionary or load the editable example. Removed entries can be shown and restored.
2. View and compare versions: Choose View / edit for an edition. Select a second edition and Compare versions to see changed terms, scope and conventions.
3. Edit a new version: Edit project, scope and entries; keep approved/rejected decisions. Full JSON also exposes manual conventions. Use a new dictionary ID for edits.
4. Save new dictionary version: Save a new immutable edition. Remove from list hides an edition without deleting files referenced by earlier runs. Corpus proposals remain available below.

## Detailed instructions

Dictionaries are auxiliary tools, not a mandatory stage of transcription, review, translation or export. Existing correction dictionaries can be selected in optional provider stages. Keep project/language/version/hash identity explicit.

Use exact canonical/manual-revision pairs and preserve rejected decisions as well as accepted entries. Publication is immutable and requires every candidate to be resolved. Translation dictionaries and source-language correction dictionaries remain conceptually separate; the editor requires an explicit dictionary kind and translation direction. A manual save records its previous edition hash and a manual-edit manifest; it never claims to be a corpus-generated proposal. Editing does not rewrite canonical transcripts.

## Next step

Return to the application and use the numbered sections and actions above. Saving a draft is separate from human approval and immutable publication.

Library visibility and custom color profiles are stored with local GUI state. Hiding is reversible through Show removed dictionaries. Copying a dictionary file into the editor still requires an explicit Save new dictionary version before it appears in the catalog. Publication rejects duplicate IDs, duplicate source terms and stale edit hashes.
